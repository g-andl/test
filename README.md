# Настрой — социальный трекер настроения

«Узнавай себя. Замечай перемены. Будь ближе к друзьям.»

Сайт: **https://g-andl.github.io/test/** · Документы: `/legal/`

Отмечай настроение несколько раз в день, веди дневник с заметками и фото, смотри календарь и статистику, добавляй друзей и следи, как у них дела. Это не медицинское приложение.

## Как устроено

| Часть | Технологии |
|---|---|
| Интерфейс | Next.js 16 (статическая сборка), React 19, TypeScript, Tailwind CSS 4, Recharts, Motion, Lucide |
| Данные | Supabase: PostgreSQL, Auth, Storage, Realtime, Edge Functions |
| Хостинг | GitHub Pages (сборка через GitHub Actions) |
| Эмодзи | Microsoft Fluent Emoji 3D (MIT), `public/emoji/` |

Сайт — набор статических страниц, вся логика и защита данных живут в Supabase. Кто что видит, проверяет сама база (правила RLS и функции в `supabase/migrations/`), а не только интерфейс.

**Приватность:**
- друзья видят всё;
- остальные пользователи — по настройке: всё (по умолчанию), только последнюю отметку или ничего;
- фото для не-друзей скрыто, пока его не разрешили.

## Возможности

- Отметки настроения несколько раз в день, дневник, календарь, статистика.
- Друзья, лента активности, уведомления (внутри приложения; push — после настройки).
- «Окно поддержки»: тёплые слова от других пользователей. Кто пишет (все / друзья / никто) и кто видит (все / друзья / только я) настраивается.
- Статусы: цветные пометки рядом с именем. Система выдаёт их сама за активность (при заходе пользователя и раз в сутки через pg_cron), администратор может выдать вручную, придумать свой и поменять цвет.
- Регистрация по имени пользователя и почте (без кодов и писем). Вход по имени или по почте.
- Админ-панель `/admin/`: аккаунты (дата создания, активность, почта, приватность), правка отметок и сообщений, смена пароля, блокировка на срок или навсегда, заявки на восстановление доступа, статусы.
- Блокировка: заблокированный входит и видит экран с сроком и причиной; все запреты проверяет база.

### Автоматические статусы

Первое подходящее правило сверху вниз (у пользователя один статус; выданный вручную система не трогает):

| Статус | Условие |
|---|---|
| Старейшина | с нами больше 180 дней и 30+ отметок |
| Стойкий | серия отметок 30 дней подряд |
| Летописец | 100+ отметок |
| Душа компании | 5+ друзей |
| Добрая душа | 10+ тёплых слов в окне поддержки |
| Огонёк | серия 7 дней подряд |
| Активист | 10+ отметок за последние 30 дней |
| Свой человек | больше 30 дней и 5+ отметок |
| Новичок | первые 14 дней |

Правила — в функции `private.auto_badge_key` (миграция `…10`). Серия считается до сегодня или вчера.

### Приватность

- **Друзья видят всё**: отметки, заметки, фото, календарь, статистику.
- **Остальные** видят то, что выбрано в настройках: всё (по умолчанию), только последнюю отметку или ничего.
  Заметки и фото из отметок по умолчанию видны и могут быть скрыты по отдельности; скрытое показывается как «скрыто» без содержания.

## Локальный запуск

Нужны Node.js 22 и Docker.

```bash
npm install
```

```bash
npx supabase start
```

Скопируй `.env.example` в `.env.local` и вставь адрес и anon-ключ из вывода `npx supabase status`. Затем:

```bash
npm run dev
```

Приложение откроется на http://localhost:3000.

## Публикация

1. Публичные настройки Supabase лежат в `.env.production`. Это адрес проекта и publishable-ключ: они видны в браузере любому посетителю, секрета в них нет.
2. Пуш в `main` запускает workflow `.github/workflows/pages.yml`: проверка, сборка и выкладка на GitHub Pages.
3. Новые миграции применяются к рабочей базе в SQL Editor Supabase или командой `npx supabase db push`.

## Push-уведомления (ещё не включены)

1. Сгенерировать ключи: `npx web-push generate-vapid-keys`.
2. Публичный ключ записать в `.env.production` как `NEXT_PUBLIC_VAPID_PUBLIC_KEY`.
3. Секреты функции — по образцу `supabase/functions/.env.example`, затем `npx supabase secrets set --env-file …` и `npx supabase functions deploy send-push`.
4. В Vault базы добавить `push_function_url` и `push_webhook_secret` (подробности — в `supabase/migrations/20261113000002_push.sql`).

## Первый администратор

Администратор — обычный аккаунт, отмеченный в таблице `admins`. После регистрации аккаунта выполни в SQL Editor Supabase
(подставь id пользователя из `auth.users`):

```sql
insert into public.admins (user_id) values ('<id пользователя>');
```

Имена с `admin`, `support`, `moder`, `nastroy` (а также `root`, `system`, `help`) обычным пользователям недоступны. Чтобы дать
администратору имя `admin`, зарегистрируй аккаунт с любым именем, добавь его в `admins` и переименуй (администраторы
проверку имени проходят):

```sql
update public.profiles set username = 'admin' where id = '<id пользователя>';
```
